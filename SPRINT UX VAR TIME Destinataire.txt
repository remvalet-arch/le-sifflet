# 🏃 SPRINT UX — VAR TIME
**Destinataire :** Claude Code
**Source :** Audit UX/UI complet (mai 2026)
**Priorités :** P0 = bloquant / P1 = haute / P2 = moyenne / P3 = faible

---

## 📋 CONTEXTE TECHNIQUE

L'app est une PWA mobile-first (viewport 390×844px). Stack apparente : SvelteKit ou Next.js App Router, Tailwind CSS, auth Google OAuth2. Les interactions UI utilisent des événements JavaScript natifs. Les composants de navigation sont une bottom-bar fixe (4 entrées) et un menu hamburger latéral.

## 🔴 P0 — CORRECTIONS CRITIQUES

---

### TICKET-001 ✅ — Confirmation de pari VAR après clic OUI/NON

**Contexte :** Quand l'utilisateur clique sur OUI ou NON dans le marché VAR, le modal se ferme immédiatement sans aucun feedback de confirmation. L'utilisateur ne sait pas si son pari a été enregistré.

**Action demandée :**
Après le clic sur OUI ou NON et la confirmation serveur, afficher un toast de succès pendant 3 secondes :

```
✅ Pari enregistré — OUI · 1 062 🪙
```

Le bouton cliqué (OUI ou NON) doit également changer d'état visuellement (fond plein, icône checkmark, texte "Misé ✓") avant la fermeture du modal pour confirmer la sélection même si le toast est manqué.

**Critère d'acceptation :** L'utilisateur sait toujours quel camp il a choisi et combien il a misé, sans avoir à naviguer vers l'historique.

---

### TICKET-002 ✅ — Champs de prono désactivés sans explication

**Contexte :** Quand un match est trop proche du coup d'envoi, les inputs de score passent en `disabled` mais aucun message n'explique pourquoi. L'utilisateur voit des champs grisés et peut croire à un bug.

**Action demandée :**
Quand `input.disabled === true` sur une carte de prono, afficher à la place des inputs un label contextuel :

```
🔒 Pronos fermés — match dans moins de 60 min
```

Ou, si le match est déjà démarré :
```
● En direct — pronos fermés
```

Supprimer les inputs désactivés et les remplacer par ce composant statique. Le score affiché (si déjà commencé) remplace les "?".

**Critère d'acceptation :** Zéro input disabled visible. L'état du match est toujours compréhensible sans action de l'utilisateur.

---

### TICKET-003 ✅ — Navigation des cartes de ligues sans lien href

**Contexte :** Les cartes de ligues dans `/ligues` utilisent des `<button>` sans `href`. Cela empêche l'ouverture dans un nouvel onglet, la navigation clavier, les lecteurs d'écran, et l'indexation.

**Action demandée :**
Remplacer le `<button>` wrappant chaque carte de ligue par un `<a href="/ligues/[id]">` tout en conservant le style visuel identique. Les boutons enfants (code d'invitation, "Plus d'options") doivent stopper la propagation du clic avec `e.stopPropagation()` pour ne pas déclencher la navigation.

```html
<!-- Avant -->
<button onClick={openLeague}>...</button>

<!-- Après -->
<a href="/ligues/{league.id}">
  ...
  <button onClick={(e) => { e.stopPropagation(); copyCode(); }}>
    {league.code}
  </button>
</a>
```

**Critère d'acceptation :** Clic droit sur une carte → "Ouvrir dans un nouvel onglet" fonctionne. Navigation clavier possible (Tab + Entrée).

### TICKET-005 ✅ (partiel — /ligues fait ; /leaderboard et /lobby restent) — Skeleton screens sur tous les états de chargement

**Contexte :** Plusieurs pages affichent du texte brut pendant le chargement ("Chargement du classement...") ou des cartes blanches vides. C'est peu professionnel et augmente la perception du temps d'attente.

**Pages concernées :**
- `/leaderboard` → onglet Classement dans la vue journée
- `/ligues` → lors du chargement des ligues
- `/lobby?league=X&round=Y` → cartes de matchs pendant le fetch

**Action demandée :**
Créer un composant `<SkeletonCard>` réutilisable qui reproduit la forme des cartes avec des blocs gris animés (shimmer effect) :

```css
@keyframes shimmer {
  0% { background-position: -200% 0; }
  100% { background-position: 200% 0; }
}
.skeleton {
  background: linear-gradient(90deg, #2D2D2D 25%, #3D3D3D 50%, #2D2D2D 75%);
  background-size: 200% 100%;
  animation: shimmer 1.5s infinite;
  border-radius: 8px;
}
```

Afficher 3 skeleton cards pendant le chargement, puis remplacer par les vraies données.

**Critère d'acceptation :** Aucun texte "Chargement..." visible. Les skeleton cards respectent les dimensions des vraies cartes.

### TICKET-006 ✅ — Indicateur de scroll horizontal sur les filtres de compétitions

**Contexte :** Les pills de filtres (Direct / Ligue 1 / Premier League / La Liga / Serie A / Bundesliga / Europe) sont scrollables horizontalement mais rien n'indique visuellement qu'il y a d'autres options hors-écran. Même constat sur les onglets Journées/Classement/Buteurs/Passeurs.

**Action demandée :**
Ajouter un gradient de fondu sur le bord droit du conteneur de pills quand du contenu est disponible hors-écran :

```css
.pills-container {
  position: relative;
  overflow-x: auto;
  scrollbar-width: none;
}
.pills-container::after {
  content: '';
  position: sticky;
  right: 0;
  width: 40px;
  background: linear-gradient(to right, transparent, #0D0D0D);
  pointer-events: none;
  flex-shrink: 0;
}
```

Le fade disparaît quand l'utilisateur a scrollé jusqu'au bout.

**Critère d'acceptation :** Sur un écran de 390px, le fade est visible à droite des pills. Il disparaît quand toutes les options sont visibles.

### TICKET-007 ✅ — Résultat de marché VAR dans le KOP après fermeture

**Contexte :** Après la fermeture d'un marché VAR (fin du timer 90s), aucune carte n'apparaît dans le KOP pour rappeler à l'utilisateur son pari en attente.

**Action demandée :**
Insérer une carte dans la timeline du KOP dès qu'un pari est enregistré, avec le statut "EN ATTENTE" :

```
⏳ 14' — Ton pari VAR
📢 Péno ?
Tu as misé : OUI · 1 062 🪙
Cote : ×2.00 — Gain potentiel : +1 062 🪙
[ EN ATTENTE DU VERDICT ]
```

Quand le verdict tombe, la carte se met à jour :
- Gagné : fond vert, afficher "✅ +1 062 🪙 — Tu avais raison !"
- Perdu : fond rouge, afficher "❌ -1 062 🪙"

**Critère d'acceptation :** L'utilisateur voit son pari dans la timeline dès qu'il est validé, et voit le résultat sans avoir à quitter la page.

### TICKET-008 ✅ — Countdown de recharge de la Sirène VAR

**Contexte :** Après utilisation, le bouton affiche "Sirène VAR (recharge 15 min)" mais sans indiquer quand exactement elle sera disponible.

**Action demandée :**
Afficher un countdown dynamique dans le bouton :

```
🔕 Sirène VAR — disponible dans 14:32
```

Le countdown se décrémente en temps réel (JS `setInterval`). Quand il atteint 0, le bouton redevient actif avec son style normal et un micro-toast "Ta sirène est rechargée 🚨".

**Critère d'acceptation :** Le countdown est visible et se décrémente en temps réel. Le bouton se réactive automatiquement sans rechargement de page.

### TICKET-009 ✅ — Bouton de déconnexion dans les Paramètres

**Contexte :** La déconnexion n'est accessible que depuis le menu hamburger (sidebar). Ce n'est pas la convention standard — les utilisateurs cherchent naturellement à se déconnecter depuis les Paramètres ou le Profil.

**Action demandée :**
Ajouter en bas de la page `/settings` une section "Compte" avec :

Le bouton doit déclencher la même action que le bouton de déconnexion existant dans le menu hamburger. Conserver également le bouton existant dans la sidebar.

**Critère d'acceptation :** La déconnexion est accessible depuis `/settings` sans ouvrir le menu hamburger.

## 🟡 P2 — AMÉLIORATIONS MOYENNES

### TICKET-010 ✅ — Overflow des noms trop longs dans la Compo

**Contexte :** Dans l'onglet Compo (composition graphique sur terrain vert), certains noms longs débordent de leur bulle (ex : "Ugochukwu", "Nottingham Forest").

**Action demandée :**
Sur les bulles de joueur, limiter le nom à 2 lignes max avec `overflow: hidden; text-overflow: ellipsis; display: -webkit-box; -webkit-line-clamp: 2;`. Réduire la taille de police de 11px à 9px si le nom dépasse 10 caractères (calcul JS simple sur `name.length`).

**Critère d'acceptation :** Aucun nom ne déborde de sa bulle sur le terrain. Le layout du terrain reste stable quel que soit le nom.

### TICKET-011 ✅ — Score "X/24" sur la page Pronos sans légende

**Contexte :** L'indicateur "13/24" sous "AUJOURD'HUI" n'est pas auto-explicatif. 13 pronos sur 24 matchs ? 13 matchs gagnés ?

**Action demandée :**
Remplacer le compteur brut par un libellé contextuel :

```
AUJOURD'HUI  13 pronos / 24 matchs
```

Ou afficher une progression en deux parties :
```
13 pronostiqués · 11 restants
```

**Critère d'acceptation :** Un nouvel utilisateur comprend immédiatement ce que signifie ce nombre sans lire les règles.

### TICKET-012 ✅ — Filtre "Ma ligue" dans le classement global

**Contexte :** Le classement global (`/leaderboard`) mélange tous les joueurs. Il n'est pas possible de voir uniquement les membres de sa ligue.

**Action demandée :**
Ajouter un deuxième onglet à côté de "Saison" et "Hall of Fame" :

```
[ Saison ] [ Ma ligue ] [ Hall of Fame ]
```

L'onglet "Ma ligue" affiche le classement filtré sur les membres de la/les ligue(s) de l'utilisateur. Si l'utilisateur a plusieurs ligues, ajouter un sélecteur dropdown pour choisir laquelle.

**Critère d'acceptation :** Un utilisateur avec des amis dans une ligue peut voir son classement relatif en 2 taps depuis le leaderboard.

**Action demandée :**
Ajouter un troisièrme à côté de "Saison", "Ma ligue"  et "Hall of Fame"  :

```
[ Saison ] [ Ma ligue ] [ Hall of Fame ] [Club Préféré] > selon les choix de l'utilisateur
```

L'onglet "*Mon Club*" affiche le classement filtré sur les membres ayant le même club de coeur (dans le profils). Si l'utilisateur a plusieurs ligues, ajouter un sélecteur dropdown pour choisir laquelle.

**Critère d'acceptation :** Un utilisateur avec un même club de coeur peut voir son classement relatif en 2 taps depuis le leaderboard.

### TICKET-017 ✅ — Ajouter aria-labels sur les boutons icônes

**Contexte :** Plusieurs boutons de l'app n'ont pas de texte visible ni d'`aria-label`, ce qui les rend inaccessibles aux lecteurs d'écran (bouton notifications en cloche, bouton "Plus d'options", FAB "Appeler la VAR").

<button aria-label="Notifications de ce match">🔔</button>

Audit complet de tous les `<button>` sans `textContent` ni `aria-label`.

### TICKET-025 ✅ — Accès direct aux Messages depuis la bottom-bar

**Contexte :** L'icône Messages (bulle) est dans le header mais n'est pas dans la bottom-bar. Pourtant un badge rouge (notification) y est visible. La bottom-bar est la navigation principale sur mobile — les Messages devraient y être accessibles.

**Action demandée :**
**Option A (recommandée) :** Remplacer l'une des 4 entrées de la bottom-bar. Le Profil et le Stade sont indispensables. Ligues et Pronos également. Envisager un pattern "More" (5ème onglet "···") qui regroupe Messages + Classement + Boutique.

```
[ 🏟 Stade ] [ 🎯 Pronos ] [ 👥 Ligues ] [ 💬 Messages ] [ 👤 Profil ]
```

**Option B :** Garder 4 onglets mais ajouter le badge de notification non lus directement sur l'icône bulle du header avec une couleur plus visible et un tap-target plus grand (min 44×44px).

**Critère d'acceptation :** L'accès aux messages ne nécessite pas l'ouverture du menu hamburger. Le badge est visible en permanence si messages non lus.

---

### TICKET-026 ✅ — Bouton retour cohérent sur toutes les pages secondaires

**Contexte :** Les pages secondaires utilisent des patterns de retour inconsistants :
- Page match → "← Matchs" (texte avec flèche)
- Page boutique → "←" (flèche seule)
- Pages du menu (rules, laws, settings) → pas de bouton retour, uniquement le menu hamburger pour naviguer

**Action demandée :**
Standardiser un composant `<BackButton>` unique utilisé sur toutes les pages secondaires :

```
← [Nom de la page parente]
```

Exemples :
- Depuis un match → "← Stade"
- Depuis la boutique → "← Menu"
- Depuis les règles → "← Menu"
- Depuis les paramètres → "← Menu"
- Depuis une conversation → "← Messages"

Ce bouton utilise `history.back()` ou une route hardcodée selon le cas.

**Critère d'acceptation :** Chaque page secondaire a un bouton retour visible, cliquable, avec le nom de la page parente. Aucune page ne nécessite le menu hamburger pour naviguer en arrière.

### TICKET-027 ✅ — Clarifier le titre de page dans le header pendant un match

**Contexte :** Dans la page d'un match, le header affiche "EN DIRECT" au centre (à la place du titre de section habituel). Cela peut induire en erreur un utilisateur qui ne se souvient plus dans quelle section de l'app il se trouve.

**Critère d'acceptation :** Le header du match affiche les deux équipes. Le badge "EN DIRECT" reste sur la carte de score, pas dans le header global.
